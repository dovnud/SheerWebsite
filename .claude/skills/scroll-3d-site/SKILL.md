# Scroll-driven 3D website: the playbook from the Sheer Davidai site

The working reference is `site/` in this repo. Read these first: `ADAPTATION_PLAN.md` (decisions and why), `TECH_TEARDOWN.md` (how the reference site works), `site/public/media/README.md` (where video and pictures go).

## Stack
Vite + TypeScript, three.js (r186), GSAP + ScrollTrigger, Lenis (smooth scroll), hand-written GLSL, fontsource fonts (Bodoni Moda display, Instrument Sans UI). No framework. Physics is a small custom JS solver (Rapier was dropped: a 4 MB WASM file is a risk under strict CSP). Deploys as static `dist/`.

## Architecture (all in `site/src/`)
- `main.ts` boots everything: theme, WebGL `World`, Lenis, scroll triggers, header state, media, gallery, story, contact overlay.
- `gl/world.ts` is the scene. One fixed full-screen canvas behind the DOM. The hero is anchored to its DOM box so it scrolls with the page. It has a debug handle `window.__replica.world` (use it in tests).
- `gl/hero-objects.ts` builds the glass hero object (variants halo / lens / curtain / ghost / sd). `monogram-paths.ts` is generated by `tools/make-monogram.mjs` from the real font outlines (opentype.js), so the 3D letters match the typeface exactly.
- `gl/projection.ts` projects a film onto the 3D letters: a second copy of the geometry, front-on UVs, additive blending at ~55% opacity so the glass still shows. Falls back to an abstract light animation.
- `gl/liquid.ts` is a screen-space liquid exit (renders the scene to a target, composites through a fluid-field shader). It is switched OFF now (`World.LIQUID_EXIT = false`); keep it as an option.
- `gl/footer.ts` + `gl/shapes.ts` are the physics pile of 3D shapes that reacts to the pointer; chapter shapes (ring, asterisk, balloon) live in `shapes.ts`.
- `theme.ts` holds design tokens (colors, metal color and metalness, shader tints). `applyTheme` writes CSS variables, so CSS and shaders share one source. Velvet is the default; `#orange`, `#marquee`, `#cobalt` in the address switch themes.
- `services.ts` is the pinned production chapters with Prev/Next. `story.ts` is the spotlight text reveal. `backdrop.ts` is the reel screen. `gallery.ts` is the picture-only gallery. `grain.ts` is a film-grain WebGL overlay. `media.ts` loads `public/media/manifest.json`.

## Techniques that worked
- Glass: `MeshPhysicalMaterial` with `transmission: 1`, thickness ~0.8, ior ~1.45, clearcoat. Draw the headline to a `CanvasTexture` (at least 2x resolution, mipmaps on) so the glass refracts real text. Use `toCreasedNormals` on extruded shapes or bevels look faceted.
- Letters as geometry: extract font outlines at build time, extrude with bevel segments (about 8), `center()` the geometry.
- Metal: `MeshStandardMaterial` metalness ~0.75, roughness ~0.34, with `RoomEnvironment` through `PMREMGenerator` for reflections. Gold is `0xc9a24b`.
- Theme in shaders: pass tint and environment colors as uniforms from the theme object.
- Text reveals: split text into wrapped lines by comparing `offsetTop` of word spans; drive per-line opacity from `scrollY`; keep the full sentence in `aria-label`. Never leave content hidden at rest without JS.
- Grain: one speck is 2 device pixels so it looks the same on desktop and phone; soft alpha (about .3) or it makes text look pixelated.

## Hard rules for this client (and good defaults for any)
1. Honor `prefers-reduced-motion`: no animation, still frames, text plainly visible.
2. Everything readable without JavaScript; the gate and effects are enhancement.
3. Nothing clips or scrolls sideways on phones (320, 390, 768, 1024, 1440 widths). Use `minmax(0,1fr)`, `overflow-x: clip` on sections with glows, `cqw` caps on big type.
4. Facts only, taken from the owner's text. No stock or generated imagery of people. Placeholders must be abstract.
5. Real footage goes in `public/media/` and `manifest.json`; paths are relative (`media/x.mp4`, no leading slash).
6. Do not buy fonts, assets or hosting; the owner decides purchases.
7. Sound is off (`AudioEngine.ENABLED = false`); do not turn it on unless asked.

## Gotchas that cost time
- Author CSS `display` beats the `hidden` attribute: keep `[hidden]{display:none!important}`.
- In a GLSL string, `#include <colorspace_fragment>` must be on its own line.
- Destination-out canvas strokes inherit the previous `strokeStyle` alpha; set `strokeStyle = '#000'` before erasing.
- Background-video and video texture autoplay need `muted` and `playsInline`; pause when off screen.
- Preview servers die between commands: restart `npx vite preview --port 4173`. Never `pkill -f` broadly.
- `git push` can be rejected if another session pushed to the branch: fetch, merge (no history rewrite), push.

## Test it (no real GPU in the cloud container)
- Playwright with software WebGL: `chromium.launch({ args: ['--use-gl=swiftshader','--enable-unsafe-swiftshader'] })`, import from `/opt/node-tools/node_modules/playwright/index.mjs`. Screenshots take ~4 s.
- Scroll in tests with `window.__replica.lenis?.scrollTo(y, { immediate: true })` and `window.scrollTo(0, y)`, then wait ~3 s.
- Existing scripts in `site/tools/`: `shoot.mjs`, `shoot-hero.mjs`, `shoot-fallbacks.mjs` (reduced motion and no-JS), `test-oneway.mjs`.
- Always check: `document.documentElement.scrollWidth <= innerWidth`, console errors, reduced-motion view, no-JS view. You cannot judge real-device frame rate or listen to audio; say so.
- Test video with a clip recorded in the browser via `MediaRecorder` (ffmpeg here has no `lavfi`).

## Process that worked
1. Sketch or render options first and let the owner choose (hero object, themes, reveal effects, colors).
2. Build behind switches or address tokens so options can be compared in the live preview.
3. Verify with screenshots (desktop and 390 px), then publish.
4. Preview: publish the built site as a private artifact (`vite build --base=./`; page.html is the body plus head content; fonts via a Google Fonts link; `files` map with `null` for stale hashed files). The artifact is private; the owner shares it from its Share menu. A public address needs GitHub Pages (Settings, Pages, Source "GitHub Actions", then run the deploy workflow after merging to `main`) or Cloudflare Pages with the owner's token.
5. Commit with clear messages on the designated branch, never create a PR unless asked.

## Starting a new page with this tech
Copy the pattern, not the content: new HTML sections in `index.html` (or a new entry page), a new scene module in `gl/` that reuses `theme.ts`, the glass and metal materials, `projection.ts` for video, and `footer.ts` for the shape pile. Keep one bold 3D idea per page and everything else quiet.
